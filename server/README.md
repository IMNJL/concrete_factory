# Сервер для отправки заявок на почту (Email API)

SMTP-порты (25/465/587) часто блокируются сетью/провайдером/хостингом, поэтому здесь используется более надёжный способ: отправка через HTTPS Email API (по умолчанию Resend).

Сервер:
- отдаёт сайт (статик) по HTTP;
- принимает заявки (заказ и форма обратной связи);
- сохраняет их в JSON на диск;
- отправляет письма через Email API по настройкам из `.env`.

## Быстрый старт

1) Перейдите в папку сервера:

```bash
cd server
```

2) Создайте `.env` на основе примера и заполните свои данные:

```bash
cp .env.example .env
```

Ключевые переменные:
- `EMAIL_PROVIDER=resend`
- `RESEND_API_KEY`
- `TO_EMAIL` — куда получать письма
- `FROM_EMAIL` — от кого отправлять (для быстрого теста подойдёт `onboarding@resend.dev`, для своего домена нужна верификация в Resend)

3) Установите зависимости и запустите:

```bash
npm install
npm start
```

Альтернативно можно запускать напрямую через Node:

- Если вы **внутри папки** `server/`: `node server.js`
- Если вы **в корне проекта**: `node server/server.js`

Для разработки (автоперезапуск при изменениях):

```bash
npm run dev
```

4) Откройте сайт через сервер (важно для отправки писем):

`http://localhost:3002/`

Если открыть `frontend/index.html` двойным кликом (через `file://`), письма отправляться не будут — нужен запущенный сервер.

## Проверка отправки

- Статус и диагностика: `GET /api/email/status`
- Тестовое письмо: `POST /api/email/test`

## Эндпоинты

- Заказ (калькулятор): `POST /api/order`
- Обратная связь: `POST /sendform`

Все заявки сохраняются локально в `server/orders.json` и `server/messages.json`, даже если отправка письма временно недоступна.

Если тестовое письмо не уходит, в ответе будет поле `hint` с подсказкой (например, про неверный API key или про запрет FROM_EMAIL без верифицированного домена).
